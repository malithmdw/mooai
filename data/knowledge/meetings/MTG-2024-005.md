# Architecture Review Board — Idempotency Store Redesign

**Date**: 2024-07-18  
**Location**: London HQ Room 2A  
**Chair**: James Whitfield (Principal Platform Architect)  
**Attendees**: Aisha Okonkwo (Payments SRE), Raj Patel (Payments Engineering), Tom Brennan (Security), Priya Sharma (Head of Payments Engineering)

---

## Purpose

Architecture review of proposals to redesign the payment idempotency store following three incidents in H1 2024 (INC-2024-002, INC-2024-007, INC-2024-011) all rooted in idempotency store failures.

---

## Background

James presented a consolidated root cause analysis:

| Incident | Idempotency Failure Mode |
|---------|------------------------|
| INC-2024-002 | DR node had no access to Redis; re-submitted 38 SWIFT MT103s |
| INC-2024-007 | Hash library bug caused collision; CHAPS payment stuck |
| INC-2024-011 | Redis async replication lost keys during failover; 214 duplicate charges |

"We've had three incidents caused by the same fundamental design weakness in 6 months. The current Redis-based idempotency store has reliability properties that are insufficient for payment safety."

## Proposals Discussed

### Proposal A: Redis with synchronous replication (WAIT command)
**Pros**: Minimal change; low migration risk  
**Cons**: WAIT command still has edge cases in cluster mode; doesn't solve cross-DC gap

### Proposal B: PostgreSQL-backed idempotency store
**Pros**: ACID guarantees; synchronous replication well-understood; survives failover cleanly  
**Cons**: Higher latency (estimate: +15 ms p50); requires schema design  
**Championed by**: Raj Patel

### Proposal C: Distributed transaction approach (two-phase commit)
**Pros**: Theoretically eliminates all idempotency risk  
**Cons**: Complexity; latency impact significant; operational burden  
**Championed by**: James Whitfield (as long-term target)

## Decision

After 45-minute discussion, the board agreed:

**Short-term (Q3 2024)**: Implement Redis WAIT command for synchronous replication to minimum 1 replica (already done post-INC-2024-011, to be formalised in architecture standard).

**Medium-term (Q4 2024)**: Migrate idempotency store for high-value payments (CHAPS, SWIFT) to PostgreSQL (Proposal B). Retain Redis for lower-value FPS and card payments.

**Long-term (2025)**: Evaluate two-phase commit design for unified idempotency approach across all payment types.

Raj to design PostgreSQL idempotency schema by 2024-08-15 (JIRA PAY-9350).
