## 1. INC-2024-006 Remediation Status

Tom presented the status of remediation actions from INC-2024-006 (JWT token exposed in 401 error response):

| Action | JIRA | Status |
|--------|------|--------|
| Security unit tests for all error handlers | SEC-301 | **Completed** 2024-05-12 |
| Mandatory DAST for all deployments | SEC-302 | **In progress** |
| Response body secret scanning in CI | SEC-303 | **In progress** |

Tom: "SEC-301 is done. We now have 142 security-specific unit tests covering error handler paths. SEC-302 and SEC-303 are the critical ones — they would have caught INC-2024-006 before production."

David: "SEC-302 is non-negotiable. I want mandatory DAST on every deployment to be live before the end of August. No exemptions for 'minor' changes."

Elena: "The response body scanner is the harder one — we need to avoid false positives on things like example tokens in documentation. I'm proposing a blocklist approach: only flag values that look like real JWTs (header.payload.signature pattern)."

## 2. DAST Policy Enforcement

Agreed approach for SEC-302 (mandatory DAST):
- OWASP ZAP API scan runs in CI pipeline after every staging deployment
- Scan duration: < 8 minutes (within acceptable CI time budget)
- HIGH or CRITICAL findings: block deployment
- MEDIUM findings: must be reviewed within 24 hours (non-blocking)
- No size exemptions (explicitly reversing the practice that contributed to INC-2024-006)

Tom to update POL-007 to reflect mandatory DAST requirement. Target: 2024-08-21.

## 3. Dependency Vulnerability Review

Elena presented the quarterly dependency CVE summary:
- 3 HIGH CVEs identified in payment service dependencies
- All 3 are being patched within the 7-day policy window
- Of note: the hashlib-utils CVE (CVE-2024-18821, caused INC-2024-007) was not identified by the automated scanner because the affected version was introduced via a transitive dependency

James: "We need to add transitive dependency scanning. Our current setup only checks direct dependencies."

Action: James to implement transitive dependency scanning in the payment services CI pipeline (JIRA SEC-305).
