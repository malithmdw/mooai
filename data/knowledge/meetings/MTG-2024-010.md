## 1. POC Objectives and Scope

The CTO presented the business case for the AI Financial Assistant POC (PROD-009):

**Objective**: Demonstrate that an AI assistant grounded in the internal knowledge base can reduce the time engineers and analysts spend searching for information by 50%.

**In scope**:
- Internal knowledge search (incident reports, runbooks, policies, architecture documents)
- Root cause analysis assistance (cross-referencing incidents for recurring patterns)
- Policy and compliance Q&A

**Out of scope (explicitly)**:
- Any customer-facing deployment
- Access to live customer data
- Transactional capabilities (payments, account changes)

AI Engineering Lead presented the target architecture: hybrid RAG (Retrieval-Augmented Generation) with Pinecone vector search, BM25 keyword search, and Anthropic Claude as the LLM. See PROD-009 for full specification.

## 2. Data Governance and Privacy Considerations

DPO raised several concerns:

1. **Training data**: No real customer PII should appear in the knowledge base. The synthetic dataset being prepared for the POC is appropriate; production data must never be used without a formal DPIA.

2. **Knowledge base access control**: The AI must enforce the same RBAC as the underlying documents. An ANALYST should not be able to use the AI to access ADMINISTRATOR-only content via indirect queries.

3. **Audit trail**: All AI queries and responses must be logged in LangSmith for audit purposes.

DPO confirmed no DPIA is required for the POC phase (synthetic data only, internal users only). A full DPIA will be required before any customer data is included.

## 3. Security Review Requirements

David Chen outlined security requirements:

- **Prompt injection**: The system must defend against attempts by users to override system instructions or access restricted content via crafted prompts
- **Data exfiltration**: Output filtering must prevent the AI from summarising restricted documents to lower-privilege users
- **Hallucination control**: All responses must be grounded in retrieved documents with citations; the AI must not generate facts not found in the knowledge base

Tom Brennan (not present, represented by David): DAST scan required before any internal demo. Pen test required before any wider rollout.

## 4. Success Criteria

Agreed POC success criteria (to be demonstrated by 2024-12-01):

| Criterion | Target |
|-----------|--------|
| Information retrieval accuracy | > 85% correct answers vs ground truth |
| Response grounding | 100% of responses cite source documents |
| RBAC enforcement | 0 cases of restricted content surfaced to lower-privilege user |
| Query latency | p95 < 5 seconds |
| Reduction in search time (user survey) | > 30% reported improvement |
