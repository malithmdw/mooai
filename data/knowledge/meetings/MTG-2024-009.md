## 1. Q3 Core Banking Incident Review

Ben presented the Q3 summary:
- 2 core banking-related incidents: INC-2024-012 (connection pool exhaustion) and INC-2024-015 (SAR export timeout)
- Both had root cause: missing database indexes combined with production-scale load not tested in staging

James: "We have a systemic problem with staging database scale. We keep discovering production performance issues in production. That has to stop."

Elena: "The staging database is currently 0.02% of production row count. The proposal to bring it to 10% is already approved in principle. We need budget and timeline from the CTO."

Action: James to escalate staging database sizing to CTO review. Target: 10% of production row count by Q1 2025.

## 2. Database Performance Improvements

Elena reported on Q3 database improvements:

| Improvement | Status | Impact |
|------------|--------|--------|
| Composite index on account_transactions(account_id, created_at) | Completed | Fixed INC-2024-012 |
| SAR export composite index on customer_data_exports | Completed | Fixed INC-2024-015 |
| ETL routing to dedicated analytics replica | Completed | Prevents INC-2024-003 recurrence |
| Statement_timeout for ETL database roles | Completed | Hard limit on runaway analytics queries |
| EXPLAIN ANALYZE gate in PR review process | In progress | Prevents missing index in new features |

## 3. Replication Lag Monitoring Updates

Aisha confirmed:
- Replication lag alert threshold reduced from 5 minutes to 2 minutes (per INC-2024-003 recommendation)
- New alert: reads from replica older than 60 seconds now routed to primary for balance-sensitive paths (mobile banking account balance endpoint)
- Replica lag dashboard updated with 1-minute resolution
