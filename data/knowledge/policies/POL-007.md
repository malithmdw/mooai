# Information Security Policy

## 1. Purpose

This policy defines Novus Bank's information security requirements for all systems and personnel handling customer or organisational data.

## 2. Data Classification

| Classification | Definition | Examples |
|---------------|-----------|---------|
| PUBLIC | Information freely shareable | Marketing materials, published rates |
| INTERNAL | Internal use only | Architecture documents, runbooks |
| RESTRICTED | Sensitive; need-to-know basis | Sanctions lists, fraud models, incident RESTRICTED docs |
| CONFIDENTIAL | Highest sensitivity | Customer PII, financial data, legal |

All documents in the knowledge base must have an `access_level` metadata field. API and AI systems must enforce role-based access per the RBAC policy (ARCH-005).

## 3. Secure Development Standards

All engineering teams must follow:

| Requirement | Standard |
|-------------|---------|
| SAST | Run on every PR; block merge on high severity |
| DAST | Run on every deployment (no size exceptions — see INC-2024-006) |
| Dependency scanning | Weekly; CVE severity HIGH or CRITICAL must be patched within 7 days |
| Secret scanning | Pre-commit hook (detect-secrets) |
| Code review | Minimum 1 security-aware reviewer for auth/payment code |
| Penetration testing | Annual external pen test; quarterly for payment systems |

## 4. Sensitive Data in Error Responses

**Prohibited**: Including any of the following in HTTP error responses, logs, or API responses visible to clients:
- JWT tokens, API keys, or authentication credentials
- Customer PII (name, address, account numbers)
- Internal system information (stack traces, SQL queries, internal hostnames)

> **Incident**: INC-2024-006 — JWT bearer token included in HTTP 401 error response. Required regulatory notification to ICO and FCA. Now drives mandatory DAST and response body scanning requirements.

## 5. Incident Classification and Reporting

Security incidents must be classified and reported per the following table:

| Category | Notification | Timeline |
|----------|-------------|---------|
| Personal data breach | ICO | Within 72 hours |
| Payment system breach | FCA | Within 24 hours |
| Suspected insider threat | HR + Legal | Immediately |
| Third-party compromise | NCSC + FCA | Within 24 hours |

## 6. Access Control

- Principle of least privilege: all access must be justified and time-limited where possible
- MFA required for all staff accessing production systems
- Privileged access management (PAM): all admin actions logged
- Quarterly access review: all production system access reviewed by department head
