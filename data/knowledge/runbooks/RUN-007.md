# Certificate Management Runbook

## 1. Purpose

Procedures for managing TLS certificates across payment scheme connectors, internal services, and API gateways. Certificate failures are a recurring root cause of payment outages (INC-2024-001, INC-2024-004).

## 2. Certificate Inventory

All production certificates are tracked in Vault under `pki/certs/`:

| Certificate | Service | Expiry | Renewal Method | Owner |
|-------------|---------|--------|---------------|-------|
| fps-connector-client | FPS (Vocalink) | 2025-03-01 | Manual (PKI team) | Payments Eng |
| bacs-connector-client | Bacs (Vocalink) | 2025-04-15 | Manual (PKI team) | Payments Eng |
| chaps-connector-client | CHAPS (BoE) | 2025-02-10 | Manual (PKI team) | Payments Eng |
| swift-gateway-client | SWIFT | 2025-01-28 | Manual (PKI team) | Payments Eng |
| api-gateway-server | External | 2024-12-01 | ACME auto | Platform Eng |
| open-banking-mtls | FCA OB Directory | 2025-06-01 | FCA portal | Open Banking |

> **Alert configuration**: All certificates above have 60-day, 30-day, and 7-day expiry alerts configured in Prometheus. These alerts are per-certificate and are independent of the cert-renewal job status.

## 3. Checking Certificate Expiry

```bash
# Check all payment connector certificates
for service in fps-connector bacs-submission-service chaps-gateway swift-gateway; do
  echo "=== $service ==="
  kubectl exec -n payments deploy/$service -- \
    openssl x509 -in /certs/client.pem -noout -dates
done

# Check against live scheme endpoint
openssl s_client -connect fps.vocalink.com:443 \
  -cert /tmp/fps-client.pem -key /tmp/fps-client.key 2>/dev/null | \
  openssl x509 -noout -dates
```

## 4. Emergency Certificate Renewal

When a certificate is expired or about to expire within 24 hours:

1. Page PKI team via `#pki-emergency` Slack channel
2. Request fast-track certificate via PKI ticket with:
   - Service name
   - CSR (see step 3)
   - Justification: "Payment service certificate — P1 escalation"
3. Generate CSR:
   ```bash
   openssl req -new -key /tmp/new-key.pem \
     -out /tmp/renewal.csr \
     -subj "/CN=fps-connector.novusbank.internal/O=Novus Bank/C=GB"
   ```
4. PKI SLA: 30 minutes for emergency, 2 business days for standard
5. Deploy new certificate:
   ```bash
   kubectl create secret tls <service>-tls \
     --cert=new-cert.pem --key=new-key.pem \
     -n payments --dry-run=client -o yaml | kubectl apply -f -
   kubectl rollout restart deployment/<service> -n payments
   ```

## 5. cert-renewal Job Monitoring

The cert-renewal cron job runs daily at 00:00 UTC. Verify it succeeded:

```bash
# Check last execution
kubectl get cronjob cert-renewal -n platform -o jsonpath='{.status.lastSuccessfulTime}'

# Check logs for failures
kubectl logs -n platform -l job-name=cert-renewal --since=24h | grep -E "ERROR|WARN|failed"
```

> **Incident lesson**: INC-2024-004 — cert-renewal job failed silently when PKI API returned 503. Now emits structured `CERT_RENEWAL_FAILED` log event that triggers a P2 alert independent of certificate expiry date.
