# Security Incident Response Runbook

## 1. Purpose

Procedures for responding to security incidents including data exposure, authentication failures, and suspected intrusions. Supplements the general on-call handbook (RUN-001).

## 2. Security Incident Classification

| Category | Examples | Immediate Action |
|----------|---------|-----------------|
| Data exposure | Token in error response, PII in logs | Rotate keys; begin forensic review |
| Authentication bypass | JWT validation failure, auth bypass | Invalidate all active sessions |
| Intrusion | Anomalous access patterns, lateral movement | Isolate affected systems |
| Insider threat | Unusual data export by staff account | Revoke access; escalate to HR/Legal |
| Supply chain | Malicious dependency, compromised image | Rebuild from known-good base |

## 3. Data Exposure Response

When sensitive data is exposed in API responses (as in INC-2024-006 — JWT tokens in 401 response):

### Step 1: Immediate Containment (0–15 minutes)
```bash
# Rollback to last known good version
kubectl rollout undo deployment/mobile-banking-api -n digital

# Rotate JWT signing keys (invalidates all active tokens)
kubectl exec -n platform deploy/auth-service -- \
  python admin.py rotate-signing-keys --reason "Precautionary post-incident" \
  --admin-token $ADMIN_TOKEN

# Verify rollback
kubectl rollout status deployment/mobile-banking-api -n digital
```

### Step 2: Forensic Review (15 minutes – 2 hours)
```bash
# Pull access logs for vulnerability window
kubectl logs deploy/mobile-banking-api -n digital \
  --since-time="2024-04-02T10:04:00Z" \
  --until-time="2024-04-02T10:33:00Z" | \
  grep "401" | jq '{path, user_agent, ip, token_in_response}'

# Check SIEM for exploitation indicators
# (SIEM query: elasticsearch.novusbank.internal/siem)
```

### Step 3: Regulatory Notification Assessment
Mandatory notifications:
- **ICO**: Any personal data exposure, within 72 hours if risk to individuals
- **FCA**: Any incident affecting banking services security, within 24 hours

DPO and Legal must be consulted before any regulatory notification is filed.

## 4. DAST and Security Testing

Post-deployment DAST scans using OWASP ZAP:
```bash
# Run DAST scan against staging environment
docker run -v $(pwd):/zap/wrk owasp/zap2docker-stable \
  zap-api-scan.py \
  -t https://mobile-banking-api-staging.novusbank.internal/openapi.json \
  -f openapi \
  -r report.html

# Critical: DAST must run for ALL deployments regardless of change size
# (INC-2024-006 occurred because DAST was skipped for a 'minor' change)
```

## 5. Key Rotation Procedures

| Secret | Rotation Frequency | Emergency Rotation Command |
|--------|-------------------|--------------------------|
| JWT signing key (RSA) | 90 days | `python admin.py rotate-signing-keys` |
| API gateway mTLS | Annual | PKI team via `#pki-emergency` |
| Database passwords | 180 days | Vault rotation (`vault write auth/...`) |
| Redis auth token | 90 days | `kubectl edit secret redis-auth -n payments` |
