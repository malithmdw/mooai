# SWIFT Gateway DR Failover Runbook

## 1. Purpose

Procedures for failing over the SWIFT gateway from DC-PRIMARY to DC-DR. This runbook was significantly updated after INC-2024-002 (MT103 double-submission during failover).

## 2. Pre-Failover Checklist (MANDATORY)

All items must be completed before initiating failover. Do not proceed if any check fails.

| # | Check | Command | Expected Result |
|---|-------|---------|----------------|
| 1 | Redis idempotency store reachable from DC-DR | `redis-cli -h redis-idempotency.dc-dr.novusbank.internal PING` | `PONG` |
| 2 | Cross-DC Redis replication lag | `redis-cli -h redis-idempotency.dc-dr.novusbank.internal INFO replication` | lag_in_seconds < 5 |
| 3 | DR SWIFT node connected to SWIFT network | `kubectl exec -n payments-dr deploy/swift-gateway -- swift-test-connection` | `CONNECTED` |
| 4 | SWIFT BIC registration matches DR node | Verify in SWIFT portal | BIC active |
| 5 | Pending SWIFT queue drained | `kubectl exec -n payments deploy/swift-gateway -- swift-queue-status` | Queue = 0 or hold payments |

> **CRITICAL**: Step 1 and 2 were not included in the original runbook. Their absence caused INC-2024-002 where the DR node lacked Redis access and re-submitted 38 MT103 messages. Do NOT skip these steps under any circumstances.

## 3. Failover Procedure

```bash
# 1. Activate HOLD_PAYMENTS on payment gateway to drain SWIFT queue
kubectl exec -n payments deploy/payment-gateway -- \
  curl -X POST http://localhost:8080/admin/circuit/hold_payments/activate \
  -H "Authorization: Bearer $ADMIN_TOKEN"

# 2. Wait for SWIFT queue to drain (max 5 minutes)
watch kubectl exec -n payments deploy/swift-gateway -- swift-queue-status

# 3. Initiate failover (notifies network team)
kubectl annotate deployment/swift-gateway -n payments \
  failover.novusbank.internal/target=dc-dr

# 4. Verify DR node is serving (post-network switch)
kubectl exec -n payments-dr deploy/swift-gateway -- \
  curl http://localhost:8080/health

# 5. Deactivate HOLD_PAYMENTS
kubectl exec -n payments deploy/payment-gateway -- \
  curl -X POST http://localhost:8080/admin/circuit/hold_payments/deactivate \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

## 4. Post-Failover Validation

Send a SWIFT canary transaction (test MT103 to Novus Bank's own BIC):
```bash
kubectl exec -n payments-dr deploy/swift-gateway -- \
  python send_canary_mt103.py --amount 1.00 --currency GBP
```

Monitor SWIFT message status for 5 minutes. If no ACK received, re-activate HOLD_PAYMENTS and page SWIFT engineering lead.

## 5. Duplicate Payment Response

If duplicate MT103 messages are detected post-failover:
1. Activate HOLD_PAYMENTS immediately
2. Identify duplicate UETRs:
   ```bash
   kubectl exec -n payments-dr deploy/swift-gateway -- \
     python find_duplicate_uetr.py --window-minutes 60
   ```
3. Issue SWIFT gpi recall for all duplicates
4. File P1 incident report
