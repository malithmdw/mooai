# Core Banking Database Operations Runbook

## 1. Purpose

Procedures for DBA and engineering teams to operate the core banking PostgreSQL cluster. See ARCH-001 for architecture.

## 2. Monitoring Replica Lag

```sql
-- Check replication lag on all replicas
SELECT
  application_name,
  state,
  sent_lsn,
  replay_lsn,
  (sent_lsn - replay_lsn) AS lag_bytes,
  replay_lag
FROM pg_stat_replication
ORDER BY replay_lag DESC;
```

Alert threshold: > 2 minutes lag → P1 (INC-2024-003 drove reduction from 5 min to 2 min).

## 3. Investigating Slow Queries

```sql
-- Top 10 slow queries (requires pg_stat_statements)
SELECT
  query,
  calls,
  total_exec_time / calls AS avg_ms,
  rows / calls AS avg_rows
FROM pg_stat_statements
ORDER BY avg_ms DESC
LIMIT 10;

-- Long-running queries (> 5 minutes)
SELECT pid, now() - pg_stat_activity.query_start AS duration, query, state
FROM pg_stat_activity
WHERE (now() - pg_stat_activity.query_start) > interval '5 minutes'
  AND state != 'idle';
```

## 4. Terminating a Blocking Query

Only terminate queries after confirming with the application team. Document in incident channel.

```sql
-- Terminate specific query by PID
SELECT pg_terminate_backend(pid)
FROM pg_stat_activity
WHERE pid = <PID_FROM_ABOVE>;
```

> **Precedent**: INC-2024-003 — ETL query causing replication lag was terminated at 13:10 UTC. Always confirm with the ETL team before terminating analytics queries.

## 5. Vacuuming

```bash
# Check autovacuum status
psql -h cbl-primary.novusbank.internal -U dbadmin -c \
  "SELECT schemaname, tablename, last_autovacuum, last_analyze FROM pg_stat_user_tables ORDER BY last_autovacuum;"

# Force manual vacuum on transactions table
psql -h cbl-primary.novusbank.internal -U dbadmin -c \
  "VACUUM ANALYZE account_transactions;"
```

## 6. Adding an Index (Non-Blocking)

Always use `CREATE INDEX CONCURRENTLY` on production to avoid table locks:

```sql
-- Example: the missing index that caused INC-2024-012
CREATE INDEX CONCURRENTLY idx_account_transactions_account_id
ON account_transactions(account_id, created_at);
```

This operation can take 10–60 minutes on large tables. Monitor progress:
```sql
SELECT phase, blocks_done, blocks_total
FROM pg_stat_progress_create_index
WHERE relid = 'account_transactions'::regclass;
```

## 7. Connection Pool Management

PgBouncer is the connection pooler. Check pool stats:

```bash
psql -h pgbouncer.novusbank.internal -p 6432 -U pgbouncer pgbouncer \
  -c "SHOW POOLS;"
```

If pool is at 100% utilisation:
1. Identify long-running connections (step 3 above)
2. Terminate offending queries if safe
3. Consider temporarily increasing `pool_size` in PgBouncer config
4. Page on-call DBA lead if unable to resolve within 10 minutes
