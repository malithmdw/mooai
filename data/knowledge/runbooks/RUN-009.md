# Fraud Detection and Sanctions Screening Runbook

## 1. Purpose

Operational procedures for the fraud detection service and sanctions screening service. See ARCH-006 and ARCH-008 for architecture context.

## 2. Fraud Detection Health Checks

```bash
# Model server health
kubectl get pods -n financial-crime -l app=fraud-detection-service

# Model serving latency
curl -s https://fraud-detection.novusbank.internal/metrics | \
  grep model_inference_latency_seconds

# False positive rate (last 5 minutes)
curl -s https://fraud-detection.novusbank.internal/metrics | \
  grep fraud_false_positive_rate_5m
```

Alert if false positive rate > 1% for 5 consecutive minutes (INC-2024-009 drove this threshold).

## 3. Emergency Threshold Override

If the fraud model is generating excessive false positives (as in INC-2024-009):

```bash
# Raise score threshold (reduces false positives, increases false negative risk)
# Current default: 0.7. Emergency range: 0.85–0.95
kubectl exec -n financial-crime deploy/fraud-detection-service -- \
  python admin.py set-threshold \
  --payment-type card_not_present \
  --threshold 0.92 \
  --reason "Bank holiday pattern shift — INC-2024-009" \
  --admin-token $ADMIN_TOKEN
```

**Document every threshold override** in the incident Slack channel with:
- Reason
- New threshold value
- Estimated duration
- Review date

> **Bank holiday override**: On bank holiday weekends, consider proactively raising CNP threshold from 0.7 to 0.85 if transaction volume patterns are anomalous. INC-2024-009 precedent.

## 4. Sanctions Screening Health Checks

```bash
# Screening service health
kubectl get pods -n compliance -l app=sanctions-screening

# SDN entry count (alert if outside expected range)
kubectl exec -n compliance deploy/sanctions-screening -- \
  psql $SANCTIONS_DB_URL -c \
  "SELECT list_name, entry_count FROM sanctions_list_versions WHERE is_current=true;"

# Expected ranges:
# OFAC_SDN: 14,500–15,500
# HMT: 3,000–4,000
# UN: 2,500–3,500
# EU: 3,500–4,500
```

## 5. Sanctions List Integrity Verification

After any database migration or upgrade (see INC-2024-010):

```bash
# Full integrity check
kubectl exec -n compliance deploy/sanctions-screening -- \
  python verify_list_integrity.py --all-lists --expected-counts

# If count is outside expected range:
# 1. Suspend wire-transfer-service immediately
# 2. Page compliance team
# 3. Re-seed from authoritative source
kubectl exec -n compliance deploy/sanctions-screening -- \
  python reseed_list.py --list OFAC_SDN --confirm
```

## 6. Sanctions Screening Unavailability

If sanctions-screening is down:
1. Payment gateway automatically activates HOLD_PAYMENTS circuit
2. Page compliance team immediately
3. Do NOT deactivate HOLD_PAYMENTS until screening is restored and validated
4. Estimated customer impact: all payment types blocked

> Regulatory requirement: Payments must not be processed without sanctions screening. There is no approved degraded-mode fallback for high-value or international payments.
