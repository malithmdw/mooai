# Cheque Imaging Service Runbook

## 1. Purpose

Operational procedures for the cheque-imaging-service. See ARCH-002 for architecture.

## 2. Clearing Cycle Schedule

| Cycle | Cut-off | Exchange | Settlement |
|-------|---------|---------|-----------|
| Morning | 08:00 UTC | 08:30 UTC | 14:00 UTC same day |
| Afternoon | 13:00 UTC | 13:30 UTC | 09:00 UTC next day |

If a cycle is missed due to system unavailability, contact PSR Scheme Operations (see INC-2024-013 for precedent on regulatory notification requirements).

## 3. Health Checks

```bash
# Service health
kubectl get pods -n cheque-imaging -l app=cheque-imaging-service

# Object storage quota
mc admin info minio.novusbank.internal/cheques

# Pending image queue depth
kubectl exec -n cheque-imaging deploy/cheque-imaging-service -- \
  curl http://localhost:8080/metrics | grep queue_depth
```

## 4. Object Storage Quota Management

Storage quota must be monitored and managed proactively (INC-2024-013).

Alert thresholds:
- 75% utilisation → P3 alert, schedule purge review
- 90% utilisation → P2 alert, immediate purge review required
- 100% utilisation → P1, clearing cycle at risk

**Manual purge (excluding legal holds):**
```bash
# List images by age
mc ls --recursive minio.novusbank.internal/cheques | \
  awk '{print $1, $4}' | sort | head -100

# Purge images older than 90 days (legal-hold tag check built in)
kubectl exec -n cheque-imaging deploy/lifecycle-manager -- \
  python purge.py --older-than 90 --dry-run  # Review output first

kubectl exec -n cheque-imaging deploy/lifecycle-manager -- \
  python purge.py --older-than 90 --confirm
```

## 5. Lifecycle Policy Management

**CRITICAL**: The lifecycle policy auto-purges images older than 90 days. This policy was disabled during INC-2024-013 to protect legal hold images and was not re-enabled, causing quota exhaustion.

```bash
# Check lifecycle policy status
mc ilm ls minio.novusbank.internal/cheques

# Re-enable lifecycle policy (after legal hold cleared)
mc ilm import minio.novusbank.internal/cheques < lifecycle-policy.json
```

After any legal hold resolution:
1. Confirm with Legal team that images are cleared for purge
2. Re-enable lifecycle policy using above command
3. Create a JIRA ticket tracking policy re-enablement and close it
4. Verify policy is active in monitoring dashboard

## 6. Resubmitting a Failed Clearing File

If the clearing file is rejected by the image-clearing-gateway:
```bash
kubectl exec -n cheque-imaging deploy/image-clearing-gateway -- \
  python resubmit.py --date 2024-08-12 --dry-run

# After confirming output is correct:
kubectl exec -n cheque-imaging deploy/image-clearing-gateway -- \
  python resubmit.py --date 2024-08-12 --confirm
```
